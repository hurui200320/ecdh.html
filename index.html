What this is

A static page for emergency encrypted text (X25519 ECIES + AES-256-GCM). You host it; friends exchange base64 envelopes over any channel — tapped, monitored, hostile. The channel just carries opaque blobs.

Full protocol spec and the pinned threat model: see README.md in the repo.

Protected

  • Message contents against tapped/monitored transport
  • Tampered or forged ciphertext — any modification fails decryption
  • Key-substitution attacks — if you do the fingerprint ceremony
  • Private key at rest — device storage and backup files are passphrase-wrapped (PBKDF2-SHA-256 800k + AES-GCM)
  • Availability — static files, works offline, a saved copy runs from file://

Not protected (by design)

  • Sender authentication — anyone with your public key can send you a decryptable message. Judge senders by the voice ceremony and message context
  • Replay — an old but genuine message can be re-sent to you
  • Metadata — blobs are visibly crypto; who talks to whom and when is visible
  • A compromised device while you use the tool (keyloggers beat any passphrase)
  • Forward secrecy against later key theft — history falls if the private key falls
  • A forgotten passphrase — the key and all its messages are gone forever

The voice ceremony

  • Call each other on a hard-to-tamper channel (voice). Agree: we use this system, for what, around when.
  • Each reads the 12 emoji under their own public key; the other checks them against the fingerprint shown for that contact.
  • Do it in both directions. 12 emoji ≈ 72 bits — has never been feasible to fake for anyone in scope.
  • Treat unexpected blobs outside agreed windows with suspicion.

Emergency habits

  • Save this page and crypto.js (same folder) offline before you need it; together they are fully self-contained.
  • Export the passphrase-encrypted backup and keep it somewhere survivable.
  • Never paste plaintext or the private key into any chat. Only envelopes and public keys.
  • If adversaries upgrade to targeted nation-state: stop, use Signal/GPG/in person instead.
